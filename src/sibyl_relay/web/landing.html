Sibyl Relay is a coordinator for autonomous agents. It routes each job to the best worker, settles on Base, delegates through Virtuals — and remembers every outcome, so the next decision is smarter. Delete the memory and the behavior breaks. That's the point.

01

The memory gate

Most routers pick a worker from a static description. Relay picks from operational memory: “this agent missed liquidity-lock evidence last time — route discovery to it only, send verification elsewhere.”

That decision survives a process restart because it lives in Sibyl Memory, not in the coordinator's RAM. Remove the memory layer and the core function stops working — which is exactly what makes memory load-bearing.

02

How it works

1 · Submit a job

Hand Relay a task

Give it a task + category (e.g. a risk review). No worker is named — Relay decides.

2 · Memory-aware routing

Reputation, recalled

It reconstructs each worker's success/failure history from Sibyl Memory and ranks them, avoiding flagged workers.

3 · Verify & settle

Prove, then pay

The result is verified before settlement. Only a valid report reaches Base payment or Virtuals delegation.

4 · Remember

Outcome persists

Success builds reliability; a failure flags the worker for review. The next session reads it back.

03

Partner stacks

Sibyl Memory Required

The durable, load-bearing foundation. WARM entities for worker profiles, COLD events for job history — recall survives restarts.

Base Onchain

Real USDC settlement for worker payments. Validated & gas-estimated against the live chain in dry-run; broadcasts a real tx when a key is set.

Virtuals Coordination

Agent-to-agent delegation via the Agent Commerce Protocol. Jobs attach a durable acp: reference.

04

Install & use

A · Install

# clone, create a venv, install with the server extra
git clone https://github.com/<you>/sibyl-relay
cd sibyl-relay
python3 -m venv .venv
.venv/bin/pip install -e '.[server]'
.venv/bin/pip install sibyl-memory-client

B · Run the dashboard

# auto-loads .env; open http://localhost:8000
.venv/bin/sibyl-relay-server

C · Configure stacks (optional)

# copy the template, paste your keys
cp .env.example .env
# BASE_PRIVATE_KEY  -> live USDC settlement
# VIRTUALS_*        -> ACP delegation

Use the REST API

# route + run a job
curl -X POST localhost:8000/api/jobs \
  -H 'content-type: application/json' \
  -d '{"task":"Review Aave v3","category":"risk","value_usdc":1.0}'

# -> routed_to, verified, payment_reference, acp_reference

Embed the library

from sibyl_relay import Coordinator, Job, \
     WorkerProfile, SibylMemoryStore

memory = SibylMemoryStore("~/.sibyl-memory/memory.db")
relay  = Coordinator(memory, workers, executor)
result = relay.run(Job("Review a protocol", "risk"))
# result.worker · result.verified · result.payment_reference

Prove memory matters

.venv/bin/python -m sibyl_relay --deletion-test
# With Sibyl:  known-failure is flagged; selected clean
# Without it:  no history; the failed worker is picked
